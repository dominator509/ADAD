# TESTING.md — ADAD Test Strategy

## Test pyramid
1. **Unit** (most) — pure logic inside each crate's library module: Zero-Clock
   epoch math, config parse/validate, error mapping, identity formatting,
   killswitch state machine transitions.
2. **Integration** — crate `tests/` dirs: vault create/unlock/seal on a loopback
   image, provider client against a mock inference server, wallet ops against a
   mock `monero-wallet-rpc`, VPS provisioner against a mock SSH target.
3. **E2E / leak battery** (few, authoritative) — against a booted image in QEMU:
   no clearnet, no DNS leak, no IPv6, no mDNS/SSDP/NetBIOS, killswitch fires on
   interface drop, zero host-disk writes across a boot cycle.
4. **Smoke** — binaries answer `--version`/health without a full boot.

## Unit test rules
- Live beside the code (`#[cfg(test)]` or the crate `src`), run by
  `scripts/test-unit.sh` (`cargo test --lib`).
- No network, no filesystem outside a tempdir, no device access.
- Deterministic: seed any randomness; Zero-Clock epoch tests pin the RNG.

## Integration test rules
- Live in each crate's `tests/` dir, run by `scripts/test-integration.sh`.
- Use loopback image files for the vault (never a real device).
- Use mock servers for all external services (inference, wallet RPC, SSH). No
  real remote, ever.
- Must clean up: detach loop devices, remove temp images, stop mock servers.

## E2E / leak-battery rules
- Live in `tests/e2e/`, orchestrated by `tests/e2e/run-leak-battery.sh`, run by
  `scripts/test-e2e.sh`.
- Run against a QEMU-booted image with a monitored virtual NIC and disk.
- Each leak class is a separate assertion with a clear pass/fail; a single leak
  fails the battery.
- On pass against a built image, write `build/leak-battery.pass` (the marker
  `production-readiness-check.sh` requires).

## Contract test rules
- The `OpenAiCompatClient` has contract tests asserting request shape against
  the OpenAI-compatible schema (works for llama-server, OpenAI, Venice).
- The Venice contract test asserts the private-model default and that anonymized
  requires the opt-in flag.

## Smoke test rules
- `scripts/smoke-test.sh` runs each built tool's `--version`. Tools not built in
  the current phase are skipped, not failed.

## Regression test rules
- Every fixed bug gets a test that reproduces it. Named `regression_<issue>`.
- Critical-flow regressions (killswitch, DMS, no-clearnet) are never allowed to
  be skipped or `#[ignore]`-d.

## Performance test rules
- Inference throughput smoke: measure tok/s against a tiny GGUF and assert it is
  within the documented band for the tier (see PROJECT_BRIEF metrics). Run in
  EP-010, not every verify (too slow).
- Killswitch latency: assert DROP-ALL within target on simulated interface drop.

## Accessibility test rules (TUI)
- Headless TUI acceptance tests assert keyboard-only reachability of every
  action and presence of a high-contrast theme. No mouse-only path.

## Security test rules
- Leak battery (above) is the primary security test surface.
- `scripts/security-check.sh` greps for committed secrets and forbidden config
  (IPv6 enable, clearnet DNS) and runs the dependency audit.
- A test attempts the DMS clock-freeze bypass and asserts it fails (DMS uses Tor
  NTP, not local clock).

## Test data rules
- No real keys, seeds, or wallets in fixtures. Use clearly-fake test vectors.
- GGUF for tests is a tiny throwaway model, not a shipped weight.

## Mocking rules
- Mock at the boundary crate's edge (HTTP mock for inference/Venice, a fake
  JSON-RPC for wallet, a local sshd-in-container or scripted stub for SSH).
- Do not mock `adad-core` logic; test it directly.

## Fixture rules
- Vault fixtures are generated by a helper that builds a loopback LUKS image at
  test time; they are not committed binaries.

## Required tests per feature
Every feature ships: at least one positive unit test, one negative/boundary
test, and — if it crosses a trust boundary or touches egress — one integration
test plus a leak-battery assertion.

## Validation matrix
| Layer | Command | Gate |
|---|---|---|
| Format | `scripts/format-check.sh` | every verify |
| Lint | `scripts/lint.sh` | every verify |
| Types | `scripts/typecheck.sh` | every verify |
| Unit | `scripts/test-unit.sh` | every verify |
| Integration | `scripts/test-integration.sh` | every verify |
| Build (static) | `scripts/build.sh` | every verify |
| Security | `scripts/security-check.sh` | every verify |
| Audit | `scripts/dependency-audit.sh` | every verify |
| Smoke | `scripts/smoke-test.sh` | every verify |
| E2E leak | `scripts/test-e2e.sh` | when harness present; required for readiness |

## Definition of test done
A change is test-done when: the new tests exist and pass, the full
`scripts/verify.sh` passes, no test was weakened to pass, and any egress-
touching change added a leak-battery assertion.
